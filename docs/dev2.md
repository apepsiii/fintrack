Rencana Pengembangan & Penyempurnaan (Roadmap) FinTrackDokumen ini berisi daftar evaluasi dari versi MVP (v1.0.0-alpha) dan rencana tindakan (Action Items) untuk menyempurnakan User Experience (UX), User Interface (UI), serta kelengkapan fitur inti aplikasi.Tahap 1: Polish & UX Improvement (Penyempurnaan Visual & Interaksi)Fokus: Membuat aplikasi terasa lebih hidup, responsif, dan mudah dibaca oleh manusia.[ ] Format Mata Uang (Thousand Separator):Masalah: Angka tampil sebagai Rp 80000, sulit dibaca cepat.Solusi: Mengimplementasikan fungsi formatting angka di sisi Golang (menggunakan package golang.org/x/text/language dan message) atau di sisi Frontend menggunakan JavaScript Intl.NumberFormat sehingga tampil menjadi Rp 80.000.[ ] Perbaikan Micro-Interactions:Masalah: Beberapa tombol statis, tidak ada feedback saat ditekan.Solusi: Menambahkan Toast Notification (notifikasi pop-up kecil di atas layar) saat transaksi berhasil disimpan. Menambahkan loading state (spinner) pada tombol Submit form menggunakan ekstensi HTMX hx-indicator.[ ] State Kosong (Empty States):Masalah: Jika belum ada transaksi sama sekali, tampilan kurang menarik.Solusi: Mendesain ilustrasi SVG minimalis yang lucu/menarik ketika riwayat transaksi, grafik statistik, atau target anggaran masih kosong.Tahap 2: Fungsionalitas Inti Transaksi (CRUD & Histori)Fokus: Memberikan kendali penuh kepada pengguna atas data uang mereka.[ ] Form Input Tanggal (Backdating):Masalah: Saat ini transaksi selalu tersimpan dengan waktu saat itu juga (CURRENT_TIMESTAMP). Tidak bisa mencatat pengeluaran kemarin.Solusi: Menambahkan field <input type="date"> dan <input type="time"> opsional di dalam Modal Bottom Sheet pencatatan.[ ] Halaman Riwayat Lengkap (Full History):Masalah: Dasbor hanya menampilkan 5 transaksi terakhir.Solusi: Membuat rute /history baru. Menambahkan tombol "Lihat Semua" di Dasbor yang mengarah ke halaman ini. Halaman ini harus mendukung Infinite Scroll atau Pagination, serta filter bulan/tahun.[ ] Detail Transaksi (Read):Masalah: Pengguna tidak bisa melihat catatan/deskripsi detail dari sebuah transaksi.Solusi: Membuat agar setiap baris transaksi bisa diklik. Saat diklik, akan memunculkan Modal/Bottom sheet berisi detail lengkap (Tanggal presisi, Kategori, Nominal, Catatan).[ ] Edit & Hapus Transaksi (Update & Delete):Masalah: Jika salah ketik nominal, pengguna tidak bisa membatalkannya.Solusi: Di dalam Modal Detail Transaksi (poin di atas), tambahkan tombol "Edit" dan "Hapus". Edit akan me- load ulang form pencatatan dengan data yang sudah ada, sementara Hapus akan menjalankan metode DELETE ke database.Tahap 3: Penyempurnaan Fitur Lanjutan (Advanced)Fokus: Memaksimalkan fitur unggulan (Selling Points) dari aplikasi.[ ] Penyempurnaan Fitur OCR (Struk):Masalah: Saat ini input <input type="file" capture="environment"> memaksa membuka kamera langsung. Tidak bisa mengambil foto struk yang sudah ada di Galeri HP.Solusi: Menyediakan dua tombol terpisah, atau menghapus atribut capture="environment" sehingga OS HP (iOS/Android) memberikan pilihan kepada pengguna: "Ambil Foto" atau "Pilih dari Galeri".[ ] Halaman Profil Editable:Masalah: Data nama pengguna dan email di halaman /profile masih statis (hardcoded).Solusi:Membuat form edit profil (Nama, Email, dan unggah Foto/Avatar).Menyimpan preferensi pengguna di database (Tabel users yang sudah direncanakan di ERD).[ ] Autentikasi Nyata (Real Auth):Masalah: Rute /login saat ini hanya melakukan redirect tanpa verifikasi.Solusi: Menerapkan sistem Session Cookie atau JWT (JSON Web Token) di Gin. Hanya pengguna yang login yang bisa melihat dasbor dan transaksinya sendiri.Catatan Implementasi untuk Developer (VS Code)Disarankan untuk mengerjakan perbaikan secara berurutan (sequential) dari Tahap 1. Pemformatan angka Rp adalah kemenangan cepat (quick win) yang akan langsung meningkatkan estetika aplikasi drastis.
